# 周期判定与恢复合同

## 事实与职责

插件决定关联 Key 的周预算何时清零，并按设置在清零后发送模型测试与邮件；不创建 Key、不改金额上限、路由或宿主原生窗口
一个 Key 关联一个账号，一个账号可关联多个 Key，各 Key 独立计费与处理
只使用主动刷新得到的唯一 `codex:604800s`、604800 秒窗口及非空观测时间、重置时间
缓存只展示，使用率下降不参与判定，旧样本与缺失窗口不触发清零
新增关联只建立基线；暂停后恢复重新建立基线，不补做历史周期

## 判定

Rref 为已确认结束时间，Tprev 为上一有效观测时间，T 和 R 为新观测及结束时间
W 为 7 天，S=R−W 为新窗口起点，容差 τ 为 2 分钟

| 条件 | 行为 |
| --- | --- |
| T≤Tprev | 保留基线，退避重查 |
| abs(R−Rref)≤τ | 同周期，只更新观测时间，不移动已确认结束时间 |
| R>Rref+τ 且 min(Tprev,Rref)−τ≤S≤T+τ | 确认新周期 |
| 新周期且 S≥Rref−τ | 正常换周，自动清零 |
| 新周期且 S<Rref−τ | 提前重置，默认自动；关闭开关后等待确认 |
| 其他边界变化 | 等待人工确认，不自动清零 |
| 目标窗口缺失、空结束时间、刷新失败 | 保留基线，有界退避 |

到点后上游仍返回旧窗口不视为换周，漏过多个周期只处理当前周期
账号通常每 5 分钟检查一次，maintenance 每轮处理有限账号和待重置 Key
多个 Key 共用账号刷新，持续无法刷新超过 1 小时显示需处理

首次确认正常换周或提前重置后，仍立即按设置自动清零一次。完成的关联进入持久的“等待周期固定”阶段；只要结束时间仍随观测时间后移，就不为同一次变化再次清零，也不追加“提前重置”事件。新建关联、暂停后恢复遇到此类窗口时只等待固定，不补清零。
等待阶段仅由有效主动刷新推进：新结束时间不再接近观测时间加 7 天，连续两次有效观测至少间隔 5 分钟，结束时间保持固定（毫秒时间戳变化不超过 1 秒），才将当次窗口确认为基线；候选继续移动则重新计时。完成后恢复正常周期识别，不补做清零。下一完整周周期已越过上次结束时间时，仍可独立按正常换周处理。
旧状态缺少等待阶段字段时保守进入等待，不重放旧清零；无法确认的迁移期间周期可能被跳过。上游未提供周期身份，同一段未固定期内的真实再次重置若与时间漂移无法区分，合并为同一周期，不重复清零。

## 清零与恢复

读取预算快照 → 用精确状态版本保存重置意图 → 调用一次 weekly 清零 → 保存完成
私有状态写入与预算清零不是同一事务，不能假定跨操作原子性
任何未完成意图都视为结果未知，包括意图落盘后进程退出、清零响应丢失、完成落盘失败
结果未知停止自动重试，读回预算只作辅助展示，不能据此证明成功

默认人工动作保留现有用量并重新建立基线，再清零一次必须明确确认可能删除期间新消费
正常失败在调用清零前发生时仍可重试；多个 Key 独立处理，已完成和结果未知的 Key 不会自动重复
排队样本超过 5 分钟时取消该次排队并重新检查当前周期，停机恢复不直接补做旧样本的清零
管理操作与维护串行，状态版本比较防止过期页面或并发进程重复领取
每个关联保留最近 10 条事件，记录时间、原因和必要错误分类，不记录原始上游错误正文
首次清零成功时每个 Key 记录一次原因与处理时间；内部等待、候选更新、周期固定及页面刷新不追加或改写该事件。真实失败与未知结果继续按原规则记录。

## 重置后的测试与邮件

只有清零返回成功且完成状态已持久化，才创建独立发送任务；首次基线、恢复、跳过与未知清零均不发送
任务按关联记录递增 ID、重置时间、当时收件地址与测试/邮件状态，多个周期不会覆盖旧任务
每次维护最多执行一个发送动作，测试先于邮件；模型测试最多等待 20 秒，SMTP 最多等待 8 秒，维护总期限 25 秒
发送前将对应状态保存为 `unknown`，完成后保存 `succeeded`；超时、断连、外部错误或完成保存失败保留未知，不自动重发
未知测试不阻挡邮件，邮件说明实际状态；管理员确认重复消费或重复投递风险后，可独立重试测试或邮件，重试不调用清零
暂停关联和关闭对应开关均停止发送，重新启用后继续排队任务；关闭测试但继续发送邮件时，该次待测试记为跳过；邮件使用重置时的收件地址，重试使用当前 SMTP 配置
每个关联保留最近完成记录与全部未完成记录，上限 32 条，全插件发送记录上限 128 条；积压满时清零继续，新通知跳过并记录事件
SMTP 配置和密码保存在插件私有状态；管理 GET 响应移除密码内容，空密码更新保留旧值，显式清除单独控制；传输只支持校验证书的 TLS/STARTTLS

## 手动发送测试

关联详情通过单独确认立即调用模型或 SMTP，不清零、不刷新账号、不更新周期基线，也不创建或修改自动发送任务
每个关联独立保存最近一次 `last_manual_probe` 和 `last_manual_mail`，含时间、状态及邮件的当时收件地址；旧状态缺失字段默认为空
手动动作检查精确版本、显式确认与关联；邮件无视自动开关但要求已保存的完整 SMTP 和非空有效邮箱，主题与正文明确为 SMTP测试
先 CAS 保存 `unknown` 意图再调用一次外部服务，成功后保存 `succeeded`；错误、超时、断连或完成落盘失败保持未知，维护和刷新不领取这些记录
两类动作共用管理串行锁，模型最多等待 20 秒、邮件 8 秒；暂停关联及自动开关关闭不阻止显式手动测试
页面使用独立确认状态、防重复点击，动作后读回持久结果；响应或刷新失败提示先刷新核实，重复测试需重新确认

## 页面与设置

主列表分列显示 Key 与关联账号、本周用量、账号使用百分比、账号预计重置和状态；名称与邮箱不重复展示。金额显示两位小数，完整精度和 Key 自身的周用量重置时间在详情查看。

提前重置开关与显示时区集中在插件设置页面，编辑后显式保存，取消不写入状态。保存使用状态版本检查，不重置基线、不触发清零，也不清除待确认或未知结果。

`display_timezone` 保存为 `browser`、`Asia/Shanghai` 或 `UTC`。旧状态缺少此字段时默认 `browser`；跟随浏览器时各浏览器按自身时区显示，选择固定时区后所有管理员统一显示。所有日期和事件使用同一选择，判定继续使用原始时间戳。状态字段为兼容性新增，不要求重新建立关联。

## 已知限制

清零同时关闭宿主周窗口，下次使用时按上海当天零点加 7 天重新开启
Key 可能比账号窗口提前约 24 小时自然清零一次，插件不改变原生到期时间
上游可能直到首次使用后才给出新周期；插件先等待有效样本并确认清零，只有启用测试时才在清零后发送模型请求
提前重置与边界校正在事实层面不能完全区分，所以保留自动开关和人工处理
停用或卸载停止未来动作，不能撤销已完成清零

判定边界由 `tests/cycles.rs` 固定，持久化失败、部分失败和并发恢复由 `tests/recovery.rs` 固定
这些逻辑测试不能替代真实宿主联调
